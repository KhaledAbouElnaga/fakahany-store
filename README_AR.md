# متجر الفكهاني

متجر عربي لبيع الفواكه والخضروات مع سلة، طلب عبر واتساب، لوحة إدارة، مخزون اختياري، مناطق توصيل اختيارية، وسجل طلبات.

## التشغيل على الكمبيوتر

1. ثبّت Node.js LTS.
2. أنشئ ملف `.env` من `.env.example`.
3. ضع قيم Supabase:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. شغّل `START-STORE.bat`.

المتجر:
`http://localhost:5173`

لوحة الإدارة:
`http://localhost:5173/admin`

## إعداد قاعدة بيانات جديدة

في Supabase SQL Editor شغّل الملفات بهذا الترتيب:

1. `supabase/schema.sql`
2. `supabase/migrations/20261002_final_features.sql`
3. `supabase/migrations/20261003_hardening.sql`
4. `supabase/migrations/20261003_store_upgrades.sql`
5. `supabase/migrations/20261003_order_cleanup.sql`
6. `supabase/migrations/20261003_custom_statuses_cleanup_security.sql`
7. `supabase/migrations/20261003_operations_upgrades.sql`

لا تضع مفاتيح Supabase الحقيقية داخل GitHub. ملف `.env` مستبعد من Git.

## فحص النسخة قبل النشر

المشروع يحتوي على GitHub Actions تقوم تلقائيًا بـ:

- تثبيت الحزم.
- فحص TypeScript.
- بناء نسخة الإنتاج.

ويمكن الفحص محليًا عبر:

```bash
npm ci
npm run typecheck
npm run build
```

## النشر

المشروع تطبيق Vite ثابت، ومجلد الإنتاج هو:

`dist`

يمكن نشره على Cloudflare Pages بإعدادات:

- Build command: `npm run build`
- Build output directory: `dist`
- Environment variables:
  - `VITE_SUPABASE_URL`
  - `VITE_SUPABASE_ANON_KEY`

ملف `public/_redirects` موجود حتى تعمل روابط مثل `/admin` مباشرة بعد النشر.

## ملاحظات أمان

- الدفع الإلكتروني غير مستخدم.
- أسعار وإجماليات الطلب يتم التحقق منها داخل Supabase قبل حفظ الطلب.
- صلاحيات الإدارة محمية بواسطة Supabase Auth وRLS.
- لا تستخدم Service Role Key داخل الواجهة الأمامية.


## التطويرات الجديدة

- زر سلة عائم على الهاتف والكمبيوتر.
- نافذة تفاصيل سريعة للمنتج.
- صفحة نجاح بعد تسجيل الطلب.
- محاولة فتح تطبيق واتساب مباشرة على الهاتف.
- مراجعة السعر والمخزون قبل الإرسال.
- زر تواصل ثابت مع المتجر.
- اختيار موعد للطلب عند تفعيل الخاصية.
- إظهار نسبة الخصم وحالة المخزون.
- تعديل جماعي للأسعار.
- استيراد منتجات من ملفات إكسل أو جداول.
- تقارير للمبيعات والمنتجات الأكثر طلبًا.
- إعادة آخر طلب من نفس الجهاز.
- مشاركة المتجر ورمز مسح.
- وصف أوضح لحالة فتح المتجر.
- إحصاءات زيارات مجهولة بدون حفظ بيانات شخصية.


## إدارة الطلبات القديمة

- يمكن أرشفة الطلبات حسب يوم أو شهر أو فترة أو حتى تاريخ محدد.
- الأرشيف قابل للاسترجاع.
- الحذف النهائي يتطلب كلمة مرور مستقلة عن كلمة مرور المدير.
- كلمة مرور الحذف تحفظ بشكل مشفر داخل قاعدة البيانات.
- كل أرشفة أو حذف أو استرجاع تسجل في سجل مستقل لا يتم حذفه مع الطلبات.


## تطويرات التشغيل الجديدة

- سجل زمني خفيف لكل طلب، بحد أقصى 30 حدثًا للطلب الواحد ويتم حذفه تلقائيًا عند حذف الطلب.
- ملاحظات داخلية للطلبات لا تظهر للعميل.
- حسابات موظفين بدعوات وصلاحيات حسب الدور.
- تنبيهات الطلبات الجديدة عبر Realtime بدون جدول تنبيهات إضافي.
- تاريخ العميل محسوب مباشرة من الطلبات الموجودة بدون تكرار بيانات العملاء.
- سجل لحركات المخزون اليدوية فقط مع حذف تلقائي للسجلات الأقدم من سنة.
- أسعار مجدولة تُحذف من جدول الجدولة تلقائيًا بعد تطبيقها.
- لوحة مؤشرات موسعة وتقارير إغلاق يومية يتم توليدها عند الطلب بدون تخزين تقارير جديدة.
- تحديد سعة لفترات التوصيل.
- حماية من تكرار نفس الطلب باستخدام معرف إرسال فريد.
- نسخة احتياطية يومية على جهاز المالك عند فتح لوحة الإدارة، بدون استهلاك مساحة تخزين إضافية في Supabase.
- تعديل الطلب من لوحة الإدارة داخل عملية واحدة مع إعادة حساب المخزون والإجمالي بأمان.
